## 2. 기술 스택 지정 및 요구사항 문서 생성

**사용자**
> 프론트는 React.js로 백엔드는 FastAPI, DB는 MariaDB, DB처리는 ORM을 사용하지 않고 SQL을 직접 사용한다. React.js는 hook, state lifting, context등을 적절하게 사용하는 것으로 기술 스택 요구사항을 작성해줘, 배포는 이러한 기술 스택에 맞는 배포 환경을 구성해줘, 일단 여기까지의 내용으로 기능적 요구사항과 비 기능적 요구사항을 requirement.md 파일로 생성해줘

**요약 답변**
- `docs/requirement.md` 생성
- 구성: 기술 스택 / 기능적 요구사항(회원·상품·주문·관리자) / 비기능적 요구사항(학습성·보안·성능·무결성·사용성·테스트) / 제약 및 범위 제외 / 배포 환경 / 다음 단계
- 핵심 결정
  - React: Hook(`useState`, `useEffect`, `useContext`, `useReducer`, Custom Hook), 상태 끌어올리기, `AuthContext`/`CartContext`
  - FastAPI: `routers` → `services` → `repositories` 3계층
  - DB: MariaDB, ORM 미사용, PyMySQL + 파라미터 바인딩, 주문은 트랜잭션
  - 배포: (초안) Docker Compose 3컨테이너 → **6장에서 로컬 직접 실행 방식으로 수정됨**
- 임의로 정한 부분: 가상 결제, JWT Access Token만 사용, 주문 취소·이미지 업로드는 후순위

## 4. 12일 × 2시간 일정 배분

**사용자**
> 12일 동안 하루 2시간씩 진행하려고 하는데 제시한 요구사항을 어떻게 배분하면 좋을지 알려줘

**요약 답변**
- 총 24시간이므로 필수(M)만 확실히 완료하고, 권장(S)·선택(C)은 보너스로 둠
- 하루 구성: 개념 20분 + 코딩 80분 + 확인·커밋 20분
- 일정(DB → 백엔드 → 프론트 → 배포 순서): 1 환경+DB, 2 백엔드 기본, 3 회원/인증 API, 4 주문 API, 5 관리자 API, 6 React 기본, 7 인증 화면, 8 장바구니+주문 화면, 9~10 관리자 화면, 11 배포, 12 마무리
- 위험 구간: 4일차(트랜잭션), 8일차(Context + useReducer), 11일차(배포. 초안은 Docker/Nginx였으나 6장에서 로컬 빌드·실행으로 변경)
- 밀릴 때 축소 순서: 관리자 화면 최소화, CSS 최소화, 테스트는 Swagger 수동 점검, 배포는 로컬 실행 확인까지

## 5. 사용자 관점 개발 흐름 (프론트 → 백엔드 → DB)

**사용자**
> 내가 원하는 방향은 사용자 관점에서 시작에서 프론트엔드-> 백엔드->DB로 이어지는 흐름으로 모든 기능을 구현하면서 진행하려고 하는데 이렇게 진행한다면 어떤 기능을 맨 처음 구현하면 좋을지?

**요약 답변**
- 첫 기능은 **상품 목록 조회**: 읽기 전용(GET), 로그인 불필요, 결과가 바로 보이고 이후 기능의 기반이 됨
- 수직 슬라이스 방식
  1. 하드코딩 배열로 React 화면 구현
  2. FastAPI `GET /api/v1/products`로 연결(처음엔 하드코딩 JSON, CORS 경험)
  3. MariaDB + `SELECT`로 교체(프론트 수정 없음)
- 구현 순서: 상품 목록 → 회원가입 → 로그인/로그아웃 → 장바구니(프론트만) → 주문하기 → 내 주문내역 → 관리자 상품·재고 → 관리자 주문·회원 → 배포
- 12일 재배치: 1~2 환경+상품목록, 3~4 회원가입+로그인, 5 장바구니, 6~7 주문+주문내역, 8~9 관리자 상품·재고, 10 관리자 주문·회원, 11 배포, 12 점검·테스트
- 주의: 로그인은 어려워서 늦게, 관리자 기능은 사용자 기능 이후, DB 테이블은 필요할 때 추가(ERD는 미리 한 장), API 응답 형식은 Swagger로 확인

## 6. 환경 전제 변경: Docker 미사용, 로컬 MariaDB 사용

**사용자**
> 위의 내용에서 Docker는 아직 학습하지 않았고, DB는 수강생 컴퓨터에 MariaDB가 설치되어 있으니 관련된 내용은 수정해줘

**요약 답변**
- `docs/requirement.md`의 Docker 관련 내용을 모두 제거하고 5장을 **로컬 PC 직접 실행 방식**으로 재작성함
  - 개발 모드: Vite(:5173) + Uvicorn(:8000) + 로컬 MariaDB(:3306)
  - 배포 모드: `npm run build` 결과를 FastAPI `StaticFiles`로 서빙(프로세스 1개, Nginx 불필요, CORS 문제 없음)
  - 로컬 환경 요구사항(ENV-01~07), DB 설정 요구사항(DB-01~06: `init.sql`/`schema.sql`/`seed.sql`, 전용 계정, `mysqldump` 백업·복원)
  - 실행 절차 8단계, 폴더 구조에서 `deploy/` 제거
- Docker, VPS, HTTPS, 상시 실행은 **확장 과제(5.6)** 로 이동
- 함께 수정한 항목: 기술 스택 표(실행/배포), NFR-D04(백업), NFR-S07(HTTPS는 확장 과제), NFR-L06(폴더), 로그 확인 방식, DB 스크립트 설명
