## 1. 유스케이스 다이어그램과 유저 스토리 보드 요청

**사용자**
> 그럼 여기까지 완성된 코드의 usecase 다이어그램과 user story보드를 생성해줘

**요약 답변**
- 대상: Level 01 완료 시점(태그 `v0.1-step3`). 구현된 기능은 **상품 목록 조회 하나**이며 나머지는 요구사항 정의서 기준의 예정 항목
- `docs/usecase_userstory.md` 생성 (텍스트 도형 기반)
  - 유스케이스 다이어그램: 사용자(방문자), 개발자 액터 / UC-01 상품 목록 조회와 하위 UC-01a~d(데이터 가져오기, 이미지 표시, 품절 구분, 로딩·오류 안내) / UC-90 API 문서, UC-91 서버 상태 확인
  - 시스템 내부 흐름도, 전체 로드맵 유스케이스 표(✅ 구현 / ⏳ 다음 / 📋 백로그)
  - UC-01 명세: 기본 흐름 7단계, 대안 흐름(품절, 0건, 서버 꺼짐, DB 오류 500, CORS)
  - 유저 스토리: 완료 7개(US-01~05, US-D1, US-D2), 다음 단계 2개(US-10 회원가입, US-11 로그인), 백로그 8개(US-20~23, US-30~32, US-40)
  - 스토리마다 "…로서 …하고 싶다, 그래서 …" 형식과 인수 조건, 요구사항 ID 연결
- 스토리 ID 규칙: 사용자 스토리 `US-숫자`, 수업·개발자용 `US-D숫자`
- 주의: US-05는 관리자 화면이 없어 SQL로 직접 바꿔 확인한 결과

## 2. 시각화 도구로 재작성 요청

**사용자**
> 미안한데 시각화 도구를 사용해서 다시 작성해줘, 그래픽 문자가 어긋나서 볼 수 가 없네, 아주 멋진 시각화가 필요해

**원인**
- 마크다운의 박스 문자(┌ ─ │ 등)와 이모지는 폰트 폭이 달라 도형이 어긋남

**요약 답변**
- Artifact 도구로 HTML 페이지를 게시 (비공개): https://claude.ai/artifact/87NaKMa3UzJHLWS5Eu6R17
- 제목 "자판기 유스케이스 보드", 라이트/다크 테마와 모바일 폭 지원, 글꼴 Noto Sans KR · IBM Plex Mono
- 구성
  1. 머리말: 완료 7 / 다음 2 / 백로그 8 현황, Git 태그 타임라인(`v0.1-step1` → `v0.1-step2` → `v0.1-step3`, 현재 위치 표시)
  2. 유스케이스 다이어그램(SVG): 액터, 시스템 경계, 하위 유스케이스 «include», 외부 시스템(MariaDB, 이미지 폴더), 예정 기능은 회색 점선 영역, 범례
  3. 요청 흐름도(SVG): 데이터 길(React → router → service → repository → MariaDB, 요청 실선 / 응답 점선)과 이미지 길(StaticFiles가 폴더에서 바로 응답)
  4. UC-01 명세: 기본 흐름과 예외 상황별 화면
  5. 유저 스토리 보드: 완료 / 다음 단계 / 백로그 3열 칸반, 카드를 누르면 스토리와 인수 조건 펼침
- 디자인 결정: 구현 = 청록, 다음 = 호박색, 백로그 = 회색, 강조 = 콜라 레드
- 게시 전에 화면을 열어 확인하지 못함 (글자 겹침·잘림 가능성은 사용자 확인 필요)
- 데이터는 `usecase_userstory.md`와 동일하며, 체크 표시는 직접 확인한 항목만 반영
