## 2. 유스케이스 명세 (UC-01 상품 목록 조회)

| 항목 | 내용 |
|------|------|
| 액터 | 사용자(방문자) |
| 목적 | 판매 중인 음료의 이름, 가격, 이미지, 재고 상태를 한눈에 본다 |
| 사전 조건 | 프론트(5173), 백엔드(8000), MariaDB가 실행 중이다 |
| 사후 조건 | 판매 중(`is_active = 1`)인 상품이 카드 목록으로 표시된다 |

**기본 흐름**
1. 사용자가 `http://localhost:5173`에 접속한다.
2. 프론트가 "불러오는 중..."을 표시하고 `GET /api/v1/products`를 호출한다.
3. 백엔드 router가 service에 요청하고, service가 repository에 요청한다.
4. repository가 `SELECT ... FROM products WHERE is_active = 1 ORDER BY id`를 실행한다.
5. 결과(JSON)가 프론트로 돌아온다.
6. 프론트가 상품마다 카드(이미지, 이름, 가격, 재고)를 그린다.
7. 브라우저가 각 카드의 이미지를 `/products/images/...` 주소에서 받아 표시한다.

**대안 흐름**
| 조건 | 결과 |
|------|------|
| 재고가 0인 상품 | 카드가 흐리게 표시되고 "품절"로 나온다 |
| 판매 중인 상품이 0건 | "상품이 없습니다."가 표시된다 |
| 백엔드가 꺼져 있음 | "오류: Failed to fetch"가 표시된다 |
| DB 접속/조회 실패 | 백엔드가 500을 응답하고(상세 원인은 서버 로그에만 기록), 프론트에 "오류: 서버 오류 (500)"이 표시된다 |
| 허용되지 않은 출처에서 호출 | CORS로 브라우저가 응답을 막는다 |

### 3.2 완료된 스토리 (Level 01)

#### US-01 상품 목록 보기 ✅
> **사용자로서** 판매 중인 음료 목록을 보고 싶다, **그래서** 무엇을 살 수 있는지 알 수 있다.

인수 조건
- [x] 접속하면 상품이 카드 목록으로 표시된다.
- [x] 카드에 이름, 가격(천 단위 쉼표, 원), 재고가 보인다.
- [x] 목록은 DB의 `products` 테이블에서 가져온다. (하드코딩 아님)
- [x] 판매 중지(`is_active = 0`)된 상품은 보이지 않는다.

관련: UC-01 / FR-P01 / 연결 구성: React → FastAPI → MariaDB

#### US-02 품절 구분 ✅
> **사용자로서** 품절된 상품을 바로 구분하고 싶다, **그래서** 살 수 없는 상품에 시간을 쓰지 않는다.

인수 조건
- [x] 재고가 0이면 "품절"이 표시되고 카드가 흐려진다.
- [x] 재고가 있으면 "재고 N개"가 표시된다.

관련: UC-01c / FR-P03(표시 부분만. 구매 차단은 주문 기능에서 구현 예정)

#### US-03 상품 이미지 보기 ✅
> **사용자로서** 음료 그림을 보고 싶다, **그래서** 상품을 직관적으로 알아볼 수 있다.

인수 조건
- [x] 각 카드에 상품 이미지가 표시된다.
- [x] 이미지는 서버의 `products/images` 폴더에서 `/products/images/...` 주소로 제공된다.
- [x] DB에는 이미지 파일이 아니라 경로만 저장된다.

관련: UC-01b / `StaticFiles` 사용

#### US-04 로딩·오류 안내 ✅
> **사용자로서** 데이터를 불러오는 중이거나 문제가 생겼을 때 알림을 받고 싶다, **그래서** 화면이 멈춘 것으로 오해하지 않는다.

인수 조건
- [x] 불러오는 동안 "불러오는 중..."이 표시된다.
- [x] 서버/통신 오류 시 "오류: ..." 메시지가 표시된다.
- [x] 상품이 0건이면 "상품이 없습니다."가 표시된다.
- [x] 서버 내부 오류의 상세 내용(SQL, DB 주소 등)은 사용자에게 노출되지 않는다.

관련: UC-01d / NFR-U03, NFR-S08

#### US-05 DB 변경이 화면에 반영됨 ✅
> **운영자로서** DB의 재고·판매 여부를 바꾸면 화면에도 바로 반영되길 원한다, **그래서** 데이터와 화면이 항상 일치한다.

인수 조건
- [x] DB에서 재고를 바꾸고 새로고침하면 화면의 재고가 바뀐다.
- [x] DB에서 `is_active`를 0으로 바꾸면 목록에서 사라진다.

비고: 관리자 화면은 아직 없다. 지금은 SQL로 직접 바꿔서 확인한다. 관리자 기능은 US-30에서 구현한다.

#### US-D1 API 문서 확인 ✅ (개발자 스토리)
> **개발자로서** 만들어진 API를 브라우저에서 바로 시험해 보고 싶다, **그래서** 프론트 없이도 백엔드를 검증할 수 있다.

인수 조건
- [x] `http://localhost:8000/docs`에서 `GET /api/v1/products`를 실행해 볼 수 있다.
- [x] `GET /`로 서버 실행 여부를 확인할 수 있다.

#### US-D2 계층 분리 구조 ✅ (개발자/학습 스토리)
> **수강생으로서** 화면·서버·DB가 어떻게 나뉘고 연결되는지 직접 확인하고 싶다, **그래서** 풀스택 구조를 이해한다.

인수 조건
- [x] 가짜 데이터 → 하드코딩 API → DB 조회 순서로 단계별로 진행했다.
- [x] router / service / repository 계층이 분리되어 있다. (SQL은 repository에만 있다)
- [x] 하드코딩 JSON을 DB 조회로 바꿀 때 프론트 코드는 수정하지 않았다.
- [x] 단계마다 Git 태그로 되돌아가 비교할 수 있다. (`v0.1-step1` ~ `v0.1-step3`)
