## 1. User Story (요구사항 원문 정리)

> 사용자(로그인)는 아직 없다. 누구나 사이트에 들어와서 사용한다.

| 단계 | User Story | 완료 조건 |
|------|-----------|-----------|
| 1 | 방문자는 사이트에 들어오면 **상품 목록**을 볼 수 있다 | DB의 판매 중인 상품이 카드로 나타난다 |
| 2 | 방문자는 상품을 클릭하면 **상품 상세 페이지**를 볼 수 있다 | 이름, 가격, 재고, 설명이 보인다 |
| 3 | 상품 상세 페이지에는 **장바구니 / 바로구매** 버튼이 있고, 누르면 해당 기능이 실행된다 | 버튼 2개가 보이고 클릭 이벤트가 연결된다 |
| 4 | 장바구니 버튼을 누르면 **담기 전에 확인**을 받고, 확인하면 장바구니에 담긴다 | 확인 → 담김 / 취소 → 담기지 않음 |
| 5 | 상세 화면에서 바로구매를 누르면 **장바구니의 모든 상품**이 구매 목록에 나오고, 상품명·단가·수량·총금액, 하단에 **결제하기** 버튼이 보인다 | 결제하기 버튼은 배치만 하고 **기능은 구현하지 않는다** |

## 2. 결정사항

### 2-1. 강의 전에 확인한 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 화면 전환 방식 | **`useState` 로 화면 전환** (라우터 라이브러리 사용 안 함) | 추가 설치가 없고 개념이 단순하다. `page` 상태 값으로 어떤 화면을 그릴지 정한다 |
| 장바구니 저장 위치 | **React 상태 + localStorage** | 백엔드에 장바구니 API와 사용자 정보가 없다. 새로고침해도 장바구니가 남는다 |
| 바로구매 범위 | **현재 상품 + 장바구니 전체** | 현재 상품이 장바구니에 없으면 1개를 넣은 뒤 장바구니 전체를 보여준다. 이미 있으면 수량은 그대로 둔다 → 구매 화면이 빈 화면이 되는 일이 없다 |
| 결과물 | **문서만 작성** | 강의하면서 직접 코드를 반영한다 |

### 2-2. 문서에서 기본값으로 정한 것 (강의 중 바꿔도 됨)

| 항목 | 기본값 |
|------|--------|
| 같은 상품을 다시 담을 때 | 새 줄을 만들지 않고 **수량 +1** |
| 재고보다 많이 담을 때 | 담지 않고 "재고가 부족합니다" 안내 (확인창도 띄우지 않음) |
| 품절 상품 (stock = 0) | 상세 화면은 볼 수 있지만 **두 버튼 모두 비활성화** |
| 담기 전 확인 방법 | 브라우저 기본 `window.confirm()` (직접 만든 모달은 이후 개선 과제) |
| 구매 화면의 수량 | **표시만** 함 (+/− 변경 기능 없음 — 요구사항 범위 밖) |
| 구매 화면 표의 컬럼 | 상품명, 단가, 수량 + **금액(단가 × 수량)** 컬럼 추가 → 총금액을 이해하기 쉽게 |
| 상세 화면 데이터 | 목록 데이터를 다시 쓰지 않고 **`GET /products/{id}` 를 새로 호출** (description 포함, 최신 재고) |
| 장바구니에 저장하는 값 | `id, name, price, image_url, stock, quantity` (담을 때의 값 그대로 저장) |
| 상단 헤더 | 제목(누르면 목록으로) + 🛒 장바구니 개수 표시 |

### 2-3. 범위 밖 (이번에는 하지 않음)

- 결제하기 버튼 기능, 주문 저장(`orders`, `order_items` 테이블)
- 장바구니 전용 페이지, 수량 변경, 삭제
- 로그인 / 사용자별 장바구니
- 결제 시점의 가격·재고 재검증 (장바구니 가격은 담을 때의 값이므로, 실제 결제를 만들 때는 서버에서 다시 확인해야 한다)

## 3. 사용할 백엔드 API (`backend/app/main.py`)

| 단계 | Method | URL | 설명 |
|------|--------|-----|------|
| 1 | GET | `/products` | 판매 중(`is_active = 1`)인 상품 목록, 가격순 |
| 2 | GET | `/products/{product_id}` | 상품 1개 (description 포함) |
| 3~5 | — | — | API 호출 없음. 프론트의 상태와 localStorage 만 사용 |

> ⚠️ 백엔드 참고사항
> - CORS 설정이 없다 → **Vite 프록시** 사용 (`vite.config.js` 에 `'/products': 'http://localhost:8000'`)
> - 이미지 파일을 서빙하지 않는다 → DB 의 `/products/images/cola.svg` 를 프론트 `public` 경로 `/images/cola.svg` 로 바꿔서 사용
> - 상품이 없을 때 `500` 을 돌려준다 (의미상 404가 맞음) → 프론트는 `res.ok` 가 아니면 모두 에러로 처리
>
> 자세한 내용은 [../app_sql_ver.md](../app_sql_ver.md) 참고

## 4. 완성 후 폴더 구조

```
frontend/src/
├── App.jsx                  ← 화면 전환(page 상태) + 장바구니 관리 (단계마다 수정)
├── App.css                  ← 공통 스타일 (단계마다 추가)
├── api/
│   └── products.js          ← [1단계] 백엔드 API 호출 함수
├── utils/
│   └── image.js             ← [1단계] 이미지 경로 변환
├── hooks/
│   └── useCart.js           ← [4단계] 장바구니 상태 + localStorage  (5단계에서 함수 추가)
├── components/
│   └── ProductCard.jsx      ← [2단계] 클릭 기능 추가
└── pages/
    ├── ProductList.jsx      ← [1단계] 상품 목록 화면
    ├── ProductDetail.jsx    ← [2단계] 상품 상세 화면 (3단계에서 버튼 추가)
    └── Checkout.jsx         ← [5단계] 구매 화면
```

## 5. 화면 흐름

```
             카드 클릭                     바로구매 클릭
 ┌──────────┐ ───────▶ ┌──────────────┐ ───────────▶ ┌──────────────┐
 │ 상품 목록  │          │  상품 상세     │              │  구매 화면     │
 │ page=list│ ◀─────── │ page=detail  │ ◀─────────── │page=checkout │
 └──────────┘  목록으로  │              │  상품으로      │ [결제하기]    │
                       │ [장바구니]     │              │  (기능 없음)   │
                       │ [바로구매]     │              └──────────────┘
                       └──────┬───────┘
                              │ 장바구니 클릭
                              ▼
                     confirm("담을까요?")
                       확인 → cart 에 추가 → localStorage 저장
                       취소 → 아무 일도 없음
```

### App 이 가지고 있는 상태 (완성 기준)

| 상태 | 예시 값 | 역할 |
|------|---------|------|
| `page` | `'list'` / `'detail'` / `'checkout'` | 지금 보여줄 화면 |
| `selectedId` | `1` | 상세 화면에서 보여줄 상품 id |
| `cart` (useCart) | `[{ id: 1, name: '콜라', price: 1500, quantity: 2, ... }]` | 장바구니 |

> 상태를 **App 한 곳**에 두는 이유: 상세 화면(담기)과 구매 화면(보여주기), 헤더(개수)가
> 모두 같은 장바구니를 써야 하기 때문이다. (상태 끌어올리기, Lifting State Up)

## 6. 실행 준비 (모든 단계 공통)

```bash
# 백엔드 (backend 폴더)
uvicorn app.main:app --reload --port 8000

# 프론트 (frontend 폴더) — vite.config.js 프록시 추가 후 재시작
npm run dev
```
